# Ripper

将本机微信聊天记录导出为可独立阅读、整理和处理的文件。

Windows 本地程序，直接读取个人微信的原始消息文字，记录指定群或联系人，并支持聊天记录和本地附件导出。**当前记录流程不使用截图或 OCR。**

当前为实验性版本，版本号保存在根目录的 [VERSION](VERSION) 文件中。已在 Windows 微信 **4.1.15.53** 上验证数据库连接、消息原文及发送人解析。其他微信版本尚未验证。本项目与微信官方无隶属关系。

| 功能 | 当前支持 |
| --- | --- |
| 记录范围 | 选定群或联系人；可选择首次导入时间范围 |
| 消息来源 | 本地聊天数据库与已提交的 WAL 事务 |
| 同步方式 | 定时同步，默认 30 秒；按消息标识去重 |
| 消息信息 | 原文、发送人、群昵称、发送时间、消息编号、来源数据库 |
| 会话浏览 | 各会话独立标签；显示序号和总条数，支持历史分页及每页条数选择 |
| 会话操作 | 顶部会话列表右键读取记录、搜索或移除对话；移除保留历史 |
| 微信头像 | 右上角显示当前会话所属账号的本地头像及昵称，点击可刷新 |
| 本地导出 | 离线 HTML 聊天目录、对话内容 Markdown、原文 Markdown、CSV、JSONL、本地文件附件及原始语音 |
| 语音转写 | 可选 Whisper Small 多语言离线识别，保留发送人、时间及原音链接 |
| 会话隐藏（实验） | 可选微信群；普通消息再次隐藏，@本人/所有人放行；停止或正常退出时恢复本次隐藏的群 |

## 运行环境

Windows 10 2004+、x64 系统。独立 EXE 版本包含运行环境和语音解码组件；精简 DLL 版本需要 .NET 10 Desktop Runtime。构建源码需要 PowerShell 7、.NET 10 SDK，以及 Visual Studio 2022 或更新版本的 C++ 桌面开发工作负载。运行发布包无需安装开发工具或单独安装语音转换软件。采集和导出无需 OCR 组件；可选的会话隐藏实验功能需要 Windows 简体中文 OCR。

## 使用

1. 将 Windows 发布包完整解压，独立 EXE 版本双击 `Ripper.exe`，DLL 版本双击 `启动.cmd`，保持微信登录。从源码构建时，分别位于 `dist/Ripper-exe/` 和 `dist/Ripper/`。
2. 点击“添加会话”，程序自动读取微信目录配置，并查找默认文档目录及已绑定账号目录，可识别自定义存储位置；发现多个账号时，从下拉列表选择。保持微信登录，点击“读取会话列表”，勾选需要记录的群或联系人。更改微信存储位置后可点击“重新识别”；未识别到时仍可手动选择账号的 `db_storage` 文件夹。目录识别仅检查文件是否存在，不读取聊天正文。
3. 首次导入范围默认“全部本地历史”，可选“最近 15 天”“最近 30 天”，也保留最近 7 天、24 小时和从添加时开始。顶部“记录会话”列表显示从 1 开始的“会话编号”，添加或关闭会话后按列表顺序连续编号。
4. 点击“开始记录”，默认每 30 秒同步一次。无需打开独立窗口；微信窗口可最小化、遮挡、切换或滚动。
5. 在“采集记录”内按会话切换标签，默认选中首个会话；没有会话时提示添加。右键会话标签可“关闭会话”，停止该会话采集并从标签和顶部列表中移除，刷新和重启后保持关闭；已采集消息及附件来源保留，通过“添加会话”重新添加即可恢复查看。记录显示“序号”列，按当前列表从 1 开始，翻页连续编号，搜索结果独立编号。底部显示总条数及当前显示范围，默认每页 100 条，可选择 50、100、200、500 条，并使用首页、上一页、下一页、末页或输入页码查看全部历史。搜索覆盖当前标签全部已采集消息的正文、会话、发送人、微信标识或群昵称，结果按页显示。切换会话保留各自页码与选中消息；修改搜索条件或每页条数后回到第一页。选中消息查看原文、发送人、群昵称、发送时间和来源。“消息原文 / 来源”内的“定位文件”可在资源管理器中选中该消息已下载的普通文件附件；非文件消息禁用，未下载或匹配不确定时提示原因。文件查找在后台进行，不复制附件。
6. 在“采集记录”内切换到具体群或联系人标签，点击顶部“导出当前聊天记录”，在所选目录新建以聊天窗口名称命名的文件夹，例如“产品讨论群”；同名时自动使用“产品讨论群 (2)”等编号，保留已有内容，Windows 不允许的字符会替换为下划线，生成该会话的 HTML、Markdown、CSV、JSONL 及本地附件和语音。导出在后台执行，底部显示当前阶段、每步完成数量与百分比及耗时，读取语音库等步骤显示滚动进度。期间可继续切换会话、搜索、查看原文、定位文件、采集及管理会话，原有采集状态保持不变；导出使用独立只读连接，导出过程中新增的消息可在下一次导出时包含。完成或失败在进度区域提示，点击“打开目录”查看文件。未选择会话、尚无记录或正在导出时禁用导出按钮；每次运行一个导出任务。关闭程序时等待该任务完成后退出。

顶部“记录会话”列表支持右键菜单：“读取记录”清除搜索条件，切换到该会话并按其导入范围单独同步一次；“搜索”切换到该会话并聚焦搜索框，可输入关键词或替换已有关键词；“移除对话”停止该会话采集并从列表和标签中隐藏，保留历史消息及来源，重新添加后可恢复。右键操作针对点击的行；其他会话保持原来的记录状态。

顶部“设置 → 模型设置”集中管理模型文件路径、下载、GPU 开关及 CPU 并发数。点击顶部“关于”打开统一窗口，一起显示当前版本号、可点击的 GitHub 项目链接和 Slogan：“Free your conversations. Own your records.”。需求整理模块已移除，导出不再生成“需求整理.md”；已有数据库中的历史需求数据仍保留。

主界面右上角显示当前会话所属微信账号的头像与昵称，添加会话后自动读取，切换不同账号的会话时同步更新，点击头像区域可刷新。头像来自该账号的本地缓存，不请求远程头像地址；微信退出、缓存缺失或账号无法确认时显示默认头像，不影响采集和导出。没有会话时显示未选择账号。

导出中的 `对话内容.md` 按发送时间整理为“发送人：内容（时间）”，不混入数据库编号或消息 XML。例如：

```text
A：导出文件请保留需求来源。 （2026-10-23 09:01:00 +08:00）
B：收到，周五完成。 （2026-10-23 09:02:00 +08:00）
C：文件 需求说明.docx （2026-10-23 09:03:00 +08:00）
```

普通文件消息会按原始文件名、大小及可用的 MD5 校验值匹配本机 `msg/file/` 中已下载的文件，复制到 `附件/<消息目录>/<原始文件名>`，并在对话内容和原文 Markdown 中添加相对链接。不同消息分目录保存，同名文件不会互相覆盖。仅有文件名和大小时，必须匹配唯一同名文件。未找到、无法校验或无法复制的文件会保留文件名并注明未导出；先在微信下载后再次导出即可重试，无需重新采集消息。

语音消息会在导出时只读连接来源账号的 `message/media_*.db`，按原始会话、本地消息编号、服务器编号和发送时间精确匹配，保存在 `语音/<消息目录>/`。SILK 语音自动转换成 `语音_年月日_时分秒.wav`，格式为 24 kHz、单声道、16 位 PCM，可用常见播放器打开；同目录保留完整原始 `.silk` 文件。两份 Markdown 默认链接到 WAV，并附原始 SILK 链接；CSV 同时提供播放文件路径、原始语音路径及转换状态。

HTML 语音气泡只展示转写文字和播放器，不展示 WAV / 原始 SILK 文件卡片、文件操作入口或成功转换说明；音频文件仍保存在导出目录中。无法内嵌播放的音频格式保留打开链接与状态提示。

转换完全在本机进行，发布包内置从附带 SDK 源码编译的解码组件，无需安装 FFmpeg 或连接转换网站。首次转换时，将按内容哈希校验的解码 DLL 缓存到 `%LOCALAPPDATA%/WeChatNotes/codecs/`，其中不保存聊天内容或音频。音频字节在内存中解码，不生成临时明文语音文件。不同消息分目录保存，同一秒发送的语音也不会覆盖。转换失败时保留原始 SILK 并注明原因，继续导出其他消息。识别到 AMR、WAV、Ogg 时保留对应扩展名，未知格式按 `.bin` 原样保存；本次不转换这些格式，启用离线语音识别后，WAV 及已成功转换的 SILK 可转为文字；AMR、Ogg 和未知格式目前仅导出原音。

导出语音时请保持微信登录。未找到音频、音频为空、匹配到多条或语音库无法读取时，会在对话中注明未导出原因，文字记录仍正常导出；可先在微信加载语音后重新导出。单条原始音频上限为 32 MiB；转换前按每包最多 5 帧估算容量，限制 PCM 缓冲不超过 32 MiB，超出时仅保留原始音频。移除会话绑定后，已保留的来源目录仍可用于历史语音导出。图片、视频和合并转发中的内嵌附件暂不提取原文件。

在导出工具栏勾选“语音转文字（离线）”，在“设置 → 模型设置”中默认勾选“启用 GPU 加速”，有兼容的 Vulkan 显卡驱动时使用 GPU，否则自动回退 CPU；取消勾选后仅使用 CPU。GPU 固定单路，避免多条语音抢占显存，发布包内含 Vulkan 识别运行库，无需另装 CUDA，继续使用原有模型文件。GPU 运行在独立的隐藏进程中，启动或识别失败时会重试当前语音并继续用 CPU，之前的结果保留；导出结束释放进程和模型。CPU 默认同时转写 4 条，模型设置中的“CPU并发”可调整为 1～8，内存紧张时可降低；多个 CPU 识别器共享一份模型，各自使用独立推理状态，并按并发数分配每路 CPU 计算线程。GPU 和 CPU 并发设置自动保存到 `%LOCALAPPDATA%/WeChatNotes/speech-settings.json`，无需重启，对下次导出生效，正在进行的导出继续使用原设置。进度区显示实际设备和回退状态，导出模型信息区分 CPU/GPU。GPU 是否更快取决于显卡、驱动和语音长度，不保证固定倍数。导出仍按原消息顺序关联结果，底部进度条在识别期间持续滚动，同时显示已完成条数和用时；语音全部处理完成后恢复百分比进度，主界面可继续操作。语音识别文字将直接写入两份 Markdown，并标注“语音转写”，保留发送人、原发送时间和原音链接。CSV 增加转写文字、状态及模型，JSONL 的 `VoiceTranscription` 保存对应结果；`Text` 和 `Message.RawContent` 保留原文，本地采集数据库不因导出转写而修改。识别失败、缺失音频或静音会注明原因，继续导出其他消息。自动识别可能有误，请结合原音核对；取消勾选可仅导出音频。

首次点击“设置 → 模型设置”，设置本机已下载的 [Whisper Small 多语言模型 ggml-small.bin](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-small.bin)，约 488 MB（466 MiB）。可填写路径或点击“选择文件”，校验后直接使用该文件，无需复制；路径保存到 `%LOCALAPPDATA%/WeChatNotes/speech-model.json`，重启后继续使用。也可点击“自动下载”，模型保存在 `%LOCALAPPDATA%/WeChatNotes/models/` 并自动设置路径。程序发布包不含模型文件和用户路径配置。模型校验 SHA256：`1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b`。下载支持进度和取消，用户可提前在其他电脑下载，再选择本机保存路径。只在下载时联网，识别全程离线；不需要 API Key，不上传音频。当前识别运行库需要 Windows 11 或更新版本，以及 [VC++ 2022 x64 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)；Windows 10 仍可使用原有采集及音频导出。CPU 识别速度取决于硬件和语音数量，主界面底部显示已完成语音条数。

本地记录在 `%LOCALAPPDATA%/WeChatNotes/records.sqlite3`。移除会话保留已记录内容；再次添加相同会话不会复制同一条消息。默认启动暂停，点击开始后补采所选范围内仍保存在微信本地库中的消息。旧版截图绑定仅保留历史记录，需要通过“添加会话”重新选择原文会话。界面不再显示“移除绑定”按钮、“需求清单”和“旧版截图”页签。

采集记录的“发送人”列直接显示已保存的联系人备注或昵称，没有名称时回退显示微信标识；资料均缺失时标注“未知发送人 / 系统”。已有原文记录无需重新采集即可显示发送人。“群昵称”作为独立补充资料保留在详情和导出中，来自该群的成员资料，与联系人备注分开保存。每次同步刷新成员资料，旧记录会在重新同步时补充当前可读取的群昵称；这是同步时的成员昵称，并非消息发送时的历史昵称。移除绑定后仍保留该会话的历史标签；导出当前会话的全部已采集记录，不受搜索条件、当前页或每页条数限制。

独立 EXE 版本无需另装 .NET，请完整保留程序目录（包括 runtimes/ 语音识别组件）。DLL 版本通过已安装的 .NET 10 Desktop Runtime 启动，也可在程序目录执行 `dotnet Ripper.dll`。本地构建会另外生成快捷方式；公开发布包使用可随目录移动的启动文件。

双击导出目录中的 `聊天记录.html` 可在浏览器离线阅读，采用接近微信的会话侧栏、文字头像和消息气泡，按发送时间展示记录。导出时根据来源微信账号与发送人标识自动匹配本人，默认将本人消息放在右侧、其他消息放在左侧；“本人”可切回自动识别或手动调整。左右样式直接保存在 HTML 中。来源不明或身份存在歧义时提示手动选择，不按昵称猜测。支持搜索、按文件或语音筛选、每页 50 条分页、原文和来源详情，以及 WAV 等浏览器支持格式的语音播放。标题栏“导出文件”提供 Markdown、CSV、JSONL 等入口。已导出的附件与语音提供“打开文件”和“定位文件”。“定位文件”通过本机 Ripper 打开 Windows 资源管理器并选中文件：先运行 v0.0.34 或更新版本一次，再重新导出；浏览器首次询问是否打开 Ripper 时选择打开。程序启动时为当前用户注册定位入口，无需管理员权限，Ripper 主界面已运行时也可调用。“浏览目录”保留普通目录链接，还可展开“文件路径”查找。请保留整个导出目录和其中的 `ripper-files.json` 文件定位索引，整体移动后继续按新位置定位。定位只接受清单中的本地附件和语音，不执行附件，不访问网络路径。页面阅读、语音播放和普通文件链接仍可在未安装 Ripper 的电脑上离线使用；直接调用资源管理器需要本机运行过新版 Ripper。

## 微信会话隐藏（实验）

在“设置 → 会话隐藏（实验）”选择群，保持微信主窗口显示、列表滚动到顶部，点击“校准会话列表”，框选左侧第一条完整会话的整行，再点击“开始隐藏”。关闭设置窗口继续运行；每次启动 Ripper 默认关闭，需要手动开始。此功能不要求把所选群添加到采集列表。

普通消息使群重新出现后，Ripper 会识别完整群名，通过定向窗口消息触发微信的“不显示”。支持微信处于后台或被其他窗口遮挡，隐藏过程不抢焦点、不移动鼠标；菜单可能短暂出现。你可以继续操作其他软件，操作微信时会暂缓隐藏。收到新的 @本人 或 @所有人后，该群放行，直到重新开始。提及以本地消息的结构化账号元数据判断，不根据正文中的昵称猜测。最小化时暂缓，也不自动滚动；目标完整群名需要位于微信自身的列表显示区域。列表滚动后会按当前画面重新定位会话行，支持第一条只显示半行的情况。群名截断、同名、窗口大小变化时暂缓，无法验证提及或菜单时暂停该规则。因此它是尽力执行的界面实验，无法保证普通消息从不短暂出现。

临时截图超时、数据更新或菜单变化会自动重试。暂停的规则可点击“重试暂停”，只重新检查暂停的群，保留已被 @ 放行的群和旧消息基线，无需恢复全部群后再开始。隐藏状态落库留出五秒确认时间。

点击“停止并恢复”或正常退出 Ripper 时，会将微信置于前台，通过本地搜索重新打开本次实际隐藏的群，恢复左侧列表显示。**打开群聊可能清除该群的未读数，原列表排序也可能变化。** 开始前已经隐藏的群不主动恢复。请保持微信登录、窗口尺寸及缩放不变，并清空微信顶部搜索框。恢复失败时会取消退出，保留待恢复清单；可查看状态重试，或在微信手动搜索打开该群后再重试。强制结束进程、关机或微信退出时无法保证立即恢复，下次运行可点击“停止并恢复”完成恢复。

规则及校准保存在 `%LOCALAPPDATA%/WeChatNotes/focus-settings.json`，待恢复清单保存在同目录的 `focus-restore.json`；不包含消息正文。隐藏仅向已核对的微信窗口及所属菜单发送鼠标消息，并在点击前重新确认会话位置和菜单；停止恢复仍会切到微信并移动鼠标，检测到新的输入时停止恢复操作。该功能额外依赖 Windows 简体中文 OCR，仅识别界面位置，不用于聊天记录采集。不同微信版本和布局可能不兼容。不会发送消息、删除聊天、修改免打扰或直接改写微信数据库。

## 实现与边界

- 只读打开微信进程以获取数据库配置，通过 HMAC-SHA512 验证数据库密钥。无注入、无进程写入，无源数据库写入。
- 读取加密数据库及 WAL 快照，验证校验码，只使用已提交事务，解密后使用独立的只读内存 SQLite 数据库。**程序不主动将密钥或完整明文聊天库写入文件**，仅选定会话的记录持久化到本地。操作系统分页、休眠和进程转储不在本程序控制范围内。
- 按本地消息标识去重；同文不同消息均保留。同条消息的内容或消息编号变化会更新已保存记录。每轮重新检查所选会话范围，兼顾断点恢复和消息变化。
- 原文不裁剪、不做 OCR、不将 HTML 实体替换为文字。JSONL 的 `Message.RawContent` 保留数据库原始正文；聊天显示正文会去除已确认的群发送人前缀。
- 普通文件附件可在导出时复制本机已有文件；不通过网络下载文件。来源目录保存在本地，移除绑定仍保留，用于历史记录导出。文件名必须为有效的本地文件名，不接受消息中的任意绝对路径或目录跳转。
- 语音在导出时读取本地媒体库，使用各分库自己的会话映射并核对完整消息标识。重复匹配时不猜测、不拼接；音频只导出到当前聊天的导出目录，不将完整明文媒体库落盘。临时音频缓冲在完成后清理。
- 图片、视频和表情保留数据库中的说明或 XML；语音可选本地离线转写。对话内容 Markdown 将媒体和引用消息转换为可读说明，已导出的文件和语音附带链接；原文 Markdown、JSONL 仍保留原始正文。
- 只覆盖已经同步到这台电脑、选定会话及所选起点之后的消息。已删除且未采集的消息无法恢复，撤回可能改变数据库中的消息内容。电脑休眠期间不会执行同步。
- 轮询间隔不是延迟保证：微信本地落库、数据库大小和写入重试会影响同步时间。微信升级可能需要重新适配。若当前版本无法通过校验，会明确提示连接失败，不会回退到 OCR。
- 仅主动下载语音模型时联网（Hugging Face，主站不可用时尝试 HF-Mirror）；以固定 SHA256 校验模型。采集、导出与语音识别在本机进行，不上传聊天内容和音频；保存的记录与导出文件为本地明文。
